# Reporting UI handoff

**Status:** Codex contract integration added 2026-08-05; Claude owns polish,
accessibility, localization and production browser tests.

## What Codex added

The dashboard now has a `Report concern` button in the existing top bar. It
opens `apps/web/src/reporting/ReportConcern.tsx`, a four-step workflow:

1. One or more universal issue codes (`WATER_BODY_SHRINKAGE`,
   `VEGETATION_LOSS`, `LAND_ENCROACHMENT`, `WASTE_DUMPING`).
2. User observation, dashboard analysis snapshot, and bounded photo picker.
3. Authority choice and truthfulness/location-sharing declarations.
4. API-created SPARC report PDF, evidence package, and manual-portal handoff.

The visual baseline is in `apps/web/src/reporting/reporting.css` and uses the
existing `--panel`, `--line`, `--ink`, `--dim`, `--accent`, and status colours.
The shell uses neutral workflow copy in the dashboard; its implementation
status is tracked here rather than shown as a prominent user-facing badge.

The workflow calls `POST /api/v1/reports` in API mode, sends the selected
dashboard analyses and boundary provenance, downloads authenticated artifacts,
and opens only the allowlisted URL returned by the server. The upload control
accepts photos only: the PDF is generated by SPARC, so there is no “PDF
evidence” upload button. No styling changes were made to Claude’s CSS.

## Frontend migration note

The browser request now sends universal location fields (`countryCode`,
`administrativeAreas`, `municipality`, `district`, `postalCode`, coordinates),
`issueCodes`, `evidenceSnapshots`, and a bounded `analysis` context. The server
returns `coverageState`, `jurisdictionRouting`, `authorityRoutes`, artifact
descriptors, and `X-Report-Access`. Tokens must stay in memory and never enter
URLs or logs. Unsupported locations still create an exportable package but do
not show a guessed authority.

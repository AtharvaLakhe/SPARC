# SPARC judging traceability checklist

**Status:** planning and release-evidence matrix  
**Rule:** a planned feature earns no implementation credit until its technical and UI evidence exists in the frozen candidate

## 1. How to use this matrix

At feature freeze, replace “planned” evidence with a commit, test record, screenshot or release artifact. If a criterion cannot meet its acceptance condition, use the listed risk/fallback and adjust the presentation claim. Do not convert documentation volume into a claim that code or science has been implemented.

## 3. P0 proof inventory

- [ ] Source commit, release version, schema version and dataset version agree.
- [ ] Nagpur and Bengaluru pack hashes match the release manifest.
- [ ] The real pack has `mock: false`; synthetic examples remain visibly labelled.
- [ ] Water, vegetation and built-up formula/mask/area tests pass.
- [ ] Common-valid coverage, scene counts, sensitivity and validation status appear in results.
- [ ] Dataset/provider, mission/product, item IDs, acquisition dates, processing baseline where known, method, CRS, citation and license are traceable.
- [ ] At least one Nagpur subdistrict passes boundary/data QA, or the release/demo explicitly uses district-only fallback; Hingna is never assumed.
- [ ] Browser success, empty, partial, invalid, `404`, `422`, `500`, upstream, missing-layer and WebGL-off states pass.
- [ ] Protected P1 job route is disabled or its `401`, `403`, `202` and rate-limit behavior passes.
- [ ] Local cold start succeeds twice with network disabled on primary and backup devices.
- [ ] Secret scan, boundary/data redistribution review and third-party notices pass.
- [ ] Presentation contains no official SDG, causal, real-time, guaranteed-accuracy, forest-loss or air-temperature misclaim.

## 4. Judge-facing claim safety

| Safe statement | Unsafe replacement to avoid |
|---|---|
| “Satellite-derived open-surface-water-area proxy” | “Official SDG water score” |
| “The mapped proxy increased/decreased over comparable windows” | “The intervention caused this change” |
| “Precomputed from versioned source observations” | “Live satellite data” |
| “Validation status is exploratory/not run/passed/failed” | “87% confident” without a defined calibrated probability |
| “NDVI vegetation activity / labelled green-cover proxy” | “Forest loss” |
| “Landsat land-surface temperature” | “Air temperature” or “heat exposure” |
| “Architecture can evolve to more districts after validation and cost tests” | “Production-ready national scale” |
| “These business models are hypotheses to validate” | “Validated market demand” |

## 5. Submission gate

- [ ] Required files and links are present.
- [ ] Demo URL/action is exact and tested; no placeholder command remains.
- [ ] Screenshots/video match the frozen candidate and show data mode.
- [ ] Every factual scientific/data-source claim links to the source register or official evidence.
- [ ] License/NOTICE and attribution travel with the submission.
- [ ] The repository’s own license remains explicitly undecided unless the user selects one; do not invent it.
- [ ] Optional 3D assets are absent unless the user supplied and approved their use/redistribution.
- [ ] Q&A owners know which claims are implemented, planned, unconfirmed or out of scope.

The final review uses [presentation and Q&A](presentation-and-qa.md) for spoken claims and [demo script](demo-script.md) for exact timing.
